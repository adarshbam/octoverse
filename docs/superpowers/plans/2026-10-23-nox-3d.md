# Nox 3D Full Experience Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the 3D Nox spike into the complete five-stage Nox experience, built on a configurable character engine. Upgrade the base character one component at a time, with the owner approving each component, before any stage work.

**Architecture:**
- **Rendering:** a React Three Fiber scene renders a procedural octopus: forward-kinematic tentacle chains rebuilt as tubes every frame, a lathed mantle, a canvas-drawn face projected onto the mantle, and instanced suckers.
- **Data:** all looks come from a `CharacterConfig`; per-stage `StagePose`s are blended by a pure pose blender driven by a pure stage reducer.
- **Interface:** all text and controls are HTML positioned over the canvas through projected screen anchors.

**Tech Stack:**
- **App:** React 19, TypeScript, Vite 8, three 0.186.1, @react-three/fiber 9.8.2, @react-three/postprocessing 3.2.2, simple-icons.
- **Tests:** Vitest (pure logic) and Playwright on system Edge (end-to-end and captures).
- **Comparison tools:** Python 3 with Pillow and NumPy.

**Spec:** `docs/superpowers/specs/2026-10-23-nox-3d-design.md`. Read it before any task; section 8.0 governs Tasks 7 to 16.

## Pattern: character component tasks (Tasks 7 to 15)

Each of these tasks upgrades one component of the base character. Every one follows these steps, and the task lists only what is specific to it.

1. **Trace:** run `python scripts/ref_grid.py <x0> <y0> <x1> <y1> spike-out/ref-<component>.png` over the task's world box and read the reference measurements from the gridded zoom.
2. **Implement** the task's interface and approach.
3. **Unit-test** any new pure function, using the task's test names.
4. **Measure:** run `node scripts/stage-capture.mjs intro spike-out/<component>.png`, then `python scripts/check_stage.py spike-out/<component>.png --panel 2`.
   - **Pass condition:** exit 0, so no regression on the panel 2 sample points.
   - **Deliberate departures:** if the owner approves departing from a sample, update that sample's tolerance in `scripts/stage_samples.json`, and note why in the review log.
5. **Owner review:** open `http://localhost:5191/review.html?component=<component>` in the browser pane and send the owner the zoomed side-by-side capture: `node scripts/review-capture.mjs <component> spike-out/review-<component>.png`.
   - **Ask:** "Approve <component> or tell me what to change."
   - **On change requests:** repeat steps 2 to 5 until they approve. **Do not start the next component task before approval.**
6. **Record** the verdict in `docs/superpowers/reviews/nox-character.md`, with the owner's words, the date and the capture copied under `docs/superpowers/reviews/assets/`. Then commit.
